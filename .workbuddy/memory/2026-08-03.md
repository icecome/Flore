## 文件夹文章递归查询修复（选中顶级目录只有子文件夹时文章显示为零）

**问题**：选中顶级目录（如 Articles），该目录下只有子文件夹没有直接订阅源时，文章计数显示为 0，文章列表也为空。

**根因**：`buildItemQuery`、`applyCountScopeFilters`、`MarkAllRead`、`ClearReadLater`、`GetItemsForExport` 等函数在筛选文件夹时，使用 `Source.folderId = ?` 精确匹配，只查询直接属于该文件夹的订阅源，**不递归子文件夹**。当文件夹下只有子文件夹时，没有直接属于该文件夹的订阅源，导致查询结果为空。

**修复**：
- `reader.go`：新增 `getAllFolderAllDescendantIDs(folderID int) ([]int, error)` 递归函数，通过 BFS 遍历获取文件夹及其所有子文件夹的 ID（深度通常 < 10，安全）
- `reader.go` `buildItemQuery`：`Source.folderId = ?` → `Source.folderId IN (?)` 使用递归 ID 列表
- `reader.go` `applyCountScopeFilters`：同理
- `reader.go` `MarkAllRead`：子查询 `WHERE folderId = ?` → `WHERE folderId IN (?)`
- `reader.go` `ClearReadLater`：同理
- `export.go` `buildExportQuery`：替换 `applyScopeFilter` 中的精确匹配为递归查询

**验证**：Go build ✓、go test ✓、tsc --noEmit ✓

## 数据库"自动备份"澄清（2026-08-03）
- 不存在独立于 ZIP 的周期性数据库自动备份。
- 周期性自动备份 = `scheduler.go` 的 `maybeRunBackup()`，受 `backupAutoEnabled` 控制（默认 false），生成 `backups/backup-*.zip`（已含数据库）。
- `reader.db.bak.timestamp` 是**恢复操作前**一次性预保护快照（`backup_restore.go:43` 的 VACUUM INTO），非定时任务；由 `cleanupOldBackups` 按 maxKeep 清理。
- `reader.db-wal`/`reader.db-shm` 为 SQLite WAL 运行文件，非备份。
- 结论：二者均与 ZIP 备份互补、不冲突；`.bak.timestamp` 是恢复回滚保险，非冗余自动备份。
