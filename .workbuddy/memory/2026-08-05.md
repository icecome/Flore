## CORS 根因修复（方案 A：hostname 匹配，不拆多端规则）
- **真机现象**：自衍生后端已能起（`~/.flore/floredesktop.log` 有 `Go backend ready`），但前端仍"获取失败"。
- **根因**：`handlers.IsLocalOrigin` 旧逻辑按 scheme+端口精确匹配（仅 `http://wails.localhost` 等），而 Wails v2.13 **macOS 生产 webview 的 Origin 是 `wails://wails.localhost`** → CORS 403 → 浏览器拦截响应 → fetch reject → "获取失败"。非后端没起，是 CORS 没放行 webview origin。
- **方案 A（已执行）**：`IsLocalOrigin` 改为 `url.Parse` 后按 `u.Hostname()` 匹配 `127.0.0.1`/`localhost`/`wails.localhost`，忽略 scheme/端口。统一覆盖 Win/Linux 生产、macOS 生产、dev 模式；精确 hostname 匹配天然挡 `wails.localhost.evil.com` 子域欺骗与外网源；CSRF 的 `X-Requested-With` 要求、`origin==""` 放行不变 → 安全性等价。不拆多端规则（scheme 差异与 OS 维度不对齐，按 OS 分反增漂移风险）。
- **改动文件**：`server/go/internal/handlers/security.go`（import `net/url` 替 `strings`）。
- **端到端验证**（standalone server 隔离实例 PORT=38123）：`wails://wails.localhost`→200(ACAO 反射)、`http://wails.localhost`→200、`http://wails.localhost:34115`→200、`http://evil.com`→403、`http://wails.localhost.evil.com`→403。Windows/Linux 无回归。
- **构建产物**：重新 `npm run build` 产 `flore-portable-darwin-amd64-0.1.0-20260803.zip`（内嵌新后端）。

## 第五轮排查（12:38）—— 根因 100% 确认：wails:// scheme 拦 fetch
- **[fe] 上报（12:35 诊断版）**：`initApiBase` 完全正常（isDesktop=true, protocol=wails:, base 设为 http://127.0.0.1:51157），但所有数据请求报 **`Load failed`**。
- **判据**：12:35 run 后端 106 个请求全 GET（壳的 health/settings×3/fetch-status），**零 OPTIONS 预检** → 带 Authorization 的 fetch 本应预检，预检根本没到后端 → **WKWebView 在网络层直接拦掉 wails:// 页面到 http://127.0.0.1 的请求**，CORS 无机会参与。
- **Wails v2.13 事实**：darwin 生产 startURL = `wails://wails/`（hostname 是 "wails" 非 wails.localhost！）；`assetserverport` 仅 dev 设置（internal/app/app_dev.go:123），**生产无 http 资产服务** → 改 scheme 为 http:// 的方案在 v2.13 不可行（页面会白屏）。
- **修复方案（已实现，12:53 构建）**：
  1. **壳绑定代理**：`apps/desktop/app.go` 新增 `ApiRequest(method, path, body) (ApiResponse{Status,CType,Body(base64)}, error)`——壳用原生 http.Client（5min 超时）转发到 `http://127.0.0.1:<goPort><path>`，带 Bearer + X-Requested-With。壳直连后端一直正常（fetch-status 轮询即证）。
  2. **前端**：`apps/web/src/utils/fetchData.ts` `request()` 桌面端优先走绑定（`getDesktopApiRequest()` 直接读 window.go，避免与 api.ts 循环依赖），base64 解码构造标准 `new Response(...)` → 所有调用方（res.ok/json/blob/text）零改动；绑定失败回退 fetch。
  3. **ATS 豁免**：`apps/desktop/build/darwin/Info.plist` 加 `NSAppTransportSecurity/NSAllowsArbitraryLoadsInWebContent`（防 <img> 等非 fetch 直连也被拦；fetch 已走绑定不受影响）。
- **待验证**：用户跑 12:53 包后，florebackend.log 的 req-debug 应出现 /api/sources /api/items 等（经壳转发）；fe-error 不再报 Load failed。

## select 控件统一 macOS 风格（17:10）
