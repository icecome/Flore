# Flore 界面文案规范

本文件是 Flore 前端界面文案的写作标准，供后续维护文案时对照。它参考 `tech-doc-style-chinese` 的规则，
并结合 Flore 的实际情况补充了项目约定。

---

## 适用范围

本规范覆盖以下内容：

- 界面上的可见文字：按钮、标签、菜单项、标题、提示、状态说明
- 面向用户的错误提示与空状态说明
- 设置项的名称与说明文字
- 通知（toast）文案

**不适用**以下内容，它们保持代码原样，不做排版调整：

- 代码标识符：变量名、函数名、类型名
- 配置键名与数据字段名，例如 `faviconMode`、`sync_file_url`
- API 路径与请求参数
- 注释与内部文档
- 日志输出（`console.error`、`slog`），面向开发者而非终端用户

## 一、基本原则

### 1.1 事实优先

- 不新增代码或上下文没有提供的能力、时间、数量、结论。
- 不把「可能」「通常」「部分」改成确定表达。
- 信息不足时保留原意或标注「待确认」，不自行补全。

### 1.2 一个概念一个术语

同一概念在界面上只用一个词，不为避免重复而轮换同义词。

| 概念 | 统一用词 | 不要写成 |
|---|---|---|
| 订阅源 | 订阅源 | 源、信源、订阅、feed（首次出现可标注「订阅源（RSS/Atom 源）」） |
| 未读 | 未读 | 未查看、待读 |
| 稍后阅读 | 稍后阅读 | 稍后读、待读清单 |
| 抓取 | 抓取 | 拉取、获取、刷新（`刷新` 仅指界面上的手动刷新按钮） |
| 备份 | 备份 | 快照、存档 |
| 恢复 | 恢复 | 回滚、还原 |
| 时间线 | 时间线 | 全部文章流、信息流 |

### 1.3 避免黑话

以下词在界面文案中不出现，需要表达对应意思时直接写清楚：

- 「对齐」→「同步到服务端」「两端一致」
- 「兜底」→「失败时退回到…」
- 「落地」「拉通」「打通」「闭环」「沉淀」「赋能」

已修正的实例：

- 「N 个源待对齐」→「N 个订阅源仅在本地」
- 「订阅对齐」分区标题→「同步订阅」

### 1.4 主语明确

- 使用「订阅源」「文章」「文件夹」「应用」作为主语，不写「它」「该」「此」。
- 用户动作与系统行为分开表述：
  - 用户动作：「点击「保存」」
  - 系统行为：「保存后设置立即生效」

## 二、排版规则

### 2.1 标点

| 内容 | 规则 | 示例 |
|---|---|---|
| 中文正文标点 | 使用全角 | `确定删除该文件夹？文件夹内的订阅源将变为未分组。` |
| 按钮、菜单、字段名 | 用直角引号 `「」` | 点击「保存」 |
| 嵌套引用 | 用 `『』` | 提示为「请选择『保存』」 |
| 省略号 | 使用 `……` | 正在生成图片…… |
| 破折号 | 使用 `——` | 主题设置——深色与浅色 |
| 冒号 | 后接解释或列举 | 同步完成：导入 12 个订阅源，更新 40 篇文章 |
| 列表项 | 完整句式统一句号；短语型可不加，同一列表内保持一致 | |

**不要**使用英文引号 `""` 或三个英文句点 `...` 表示省略。

### 2.2 中文与英文、数字之间的空格

中文与英文单词、缩写、阿拉伯数字之间加一个半角空格：

- ✅ `使用 HTTP 304 协商跳过`
- ✅ `等待 3 秒`
- ✅ `每 3 天最多检查一次`
- ❌ `使用HTTP 304协商跳过`

数字与单位之间同样加半角空格：

- ✅ `500 ms`、`10 秒`、`24 小时`
- 百分号紧贴数字：`50%`

### 2.3 行内代码

界面文案中不出现行内代码标记。若必须提到配置项或路径，写成用户能识别的名称，例如「抓取超时」而非 `fetchTimeout`。

## 三、界面文案分类

### 3.1 按钮

**说明动作和对象，不重复所在分区标题。**

| 原则 | 示例 |
|---|---|
| 用动词开头 | 「导入 OPML」「立即同步」「清理过期备份」 |
| 不用「确定」「确定？」处理具体动作 | ❌ 确定 → ✅ 导入 |
| 危险动作用动词明确后果 | ✅ 删除订阅源（而非「确定」） |
| 进行中状态用「……」表示未完成 | 「导入中……」「同步中……」 |

**禁用词**：「确定」「确定？」——无法表达动作内容。「取消」在弹窗中表示「关闭且不保存」，不要同时用「取消」表示「取消订阅」或「取消收藏」。同一界面内三者不得共用同一按钮。

### 3.2 标签页与分区标题

- 用名词短语，不带句号。
- 不使用「设置」这类与所在页面重复的词。
- 分区之间层级一致，不混用名词与动宾结构。

### 3.3 错误提示

**错误提示说明三件事：发生了什么、影响是什么、如何恢复。**

结构：`发生了什么 + 如何恢复`

- ✅ `WebDAV 认证失败，请检查用户名和密码`
- ✅ `搜索失败，请检查网络连接后重试`
- ❌ `操作失败`
- ❌ `internal_server_error`

**规则**：

- 错误提示一律使用 `'error'` 类型（红色 + 警示图标）。
- 后端返回的英文错误必须先翻译，不得直接显示。
  翻译表见 `apps/web/src/utils/backendError.ts`，新增后端错误时同步补充。
- 不显示堆栈、文件路径、端口号等实现细节。
- 用户无法自行恢复的错误，也要说明现象而非「请联系管理员」了事。

### 3.4 空状态

**区分四种情况，不得共用一条文案。**

| 情况 | 图标 | 文案结构 |
|---|---|---|
| 没有数据 | 中性 | 说明当前为空 + 下一步做什么 |
| 尚未创建 | 中性 | 说明尚未创建 + 如何创建 |
| 搜索无结果 | 搜索类 | 包含搜索词 + 调整建议 |
| 加载失败 | 警示 | 说明失败 + 重试入口 |

**已修正**：`ArticleList.tsx` 此前对「搜索无结果」「搜索失败」「未读已清空」「列表为空」四种情况共用「没有更多文章了」，现拆分为 `ListEmptyState` 组件分别处理。

### 3.5 设置项说明

**说明文字必须补充标题没有的信息，不复述标题。**

| 原则 | 示例 |
|---|---|
| 说明实际影响 | 「抓取从已完成抓取的源不再重新下载文章」 |
| 说明取值含义 | 「相对时间显示「3 小时前」，绝对时间显示具体日期」 |
| 说明副作用 | 「修改仅影响此后新增的订阅源」 |
| 说明前置条件 | 「关闭托盘后，「最小化到托盘」将改为最小化到任务栏」 |
| 说明隐私影响 | 「选择 Yandex 会把订阅的站点域名发送给第三方服务」 |

❌ 复述式（禁止）：

- 「日期格式」/「文章时间的显示格式。」
- 「显示密度」/「调整文章列表的行间距。」

### 3.6 危险操作确认

**写清操作对象、影响范围、是否可撤销。**

结构：`动词 + 对象 + 影响 + 可撤销性`

- ✅ `确定将「技术」文件夹的 128 篇未读文章标记为已读？此操作无法撤销。`
- ✅ `确定删除该文件夹？文件夹内的订阅源将变为未分组。`
- ❌ `确定吗？`
- ❌ `操作成功`

**范围性动词**（删除、清空、覆盖）一律需要确认；状态标记类操作若不可撤销，同样需要确认。

### 3.7 进度与等待

- 进行中：动词 + 「中……」+ 省略号，例如「正在抓取最新文章……」
- 完成：说明结果数量，例如「同步完成：导入 12 个订阅源，更新 40 篇文章」
- 耗时较长（超过 10 秒）需给出进度或阶段说明，不能只有静态文字

## 四、术语表

### 4.1 产品与界面

| 术语 | 说明 |
|---|---|
| Flore | 产品名。界面出现产品名时使用「Flore」，不使用「RSS 阅读器」等通用类别词 |
| 订阅源 | 一条 RSS/Atom 订阅。首次出现可标注英文原名 |
| 文件夹 | 订阅源的分组容器。不使用「分类」「目录」 |
| 时间线 | 「全部文章」视图。不使用「信息流」 |
| 稍后阅读 | 稍后阅读清单。对应数据字段 `isReadLater` |
| 全文模式 | 从原文提取正文的阅读方式 |
| 网页模式 | 在应用内嵌 iframe 打开原文 |
| 浏览器打开 | 在系统浏览器中打开原文 |

### 4.2 技术术语在界面上的写法

| 内部写法 | 界面写法 | 说明 |
|---|---|---|
| `API token` | 访问令牌 | 不显示 `token` |
| `OPML` | OPML | 保留英文缩写，首次出现补充「订阅列表文件」 |
| `WebDAV` | WebDAV | 保留官方写法 |
| `Miniflux` / `FreshRSS` | Miniflux / FreshRSS | 保留产品官方拼写 |
| HTTP 304 | HTTP 304 | 保留协议术语，可加中文解释「内容未变化的源会跳过重复下载」 |
| favicon | 站点图标 | 不显示 `favicon` |
| localStorage / SQLite | 不出现在界面 | 属于实现细节 |

## 六、新增文案时的检查清单

新增或修改界面文案时，逐条确认：

- [ ] 事实与代码实现一致，没有承诺尚不存在的能力
- [ ] 术语与本文档术语表一致
- [ ] 没有使用黑话词
- [ ] 标点为全角；引号使用 `「」`；省略号使用 `……`
- [ ] 中文与英文/数字之间有半角空格
- [ ] 按钮说明动作和对象，不使用「确定」
- [ ] 错误提示包含「发生了什么 + 如何恢复」，并使用 `'error'` 类型
- [ ] 空状态与实际原因匹配，四种情况未共用文案
- [ ] 设置项说明补充了标题之外的信息
- [ ] 危险操作确认包含对象、范围、可撤销性
- [ ] 未暴露实现细节（端口、路径、堆栈、内部字段名）

## 七、维护约定

- 本文件与代码同仓库维护。修改界面文案时，如果引入了新的概念或术语，同步更新第 4 节术语表。
- `apps/web/src/utils/backendError.ts` 是后端错误到中文文案的唯一映射点。新增后端错误字符串时，同步在该文件中补充映射，避免英文直接显示给用户。
