## 零、v1 → v2 修订对照（审查结论落地）

| 位置 | v1 原设计 | v2 修订 | 理由 |
|------|-----------|---------|------|
| T-v02-02 | 导入弹窗加 7/30/全部选择器 + handler 透传 days | 砍掉，改全局设置 `initialFetchWindowDays` 统一生效 | OPML 只含源列表，导入时选窗口无意义；下游 fetcher 才是生效点 |
| T-v02-04 | 后端新增 filter 参数 + 前端分段控件 | **移至 v0.3**；v0.2 阶段纯前端客户端筛选，不碰后端接口 | 小数据量下前端分组够用；后端参数涉时区边界，推迟；v0.2 核心是"不吓跑人"，未读分层属体验优化 |
| T-v03-01 | CI 自动 bump 并提 PR 到 winget/brew 仓库 | 去掉自动提交，改发版后手动提 PR | 外部仓库 PR 自动化成本远大于收益（手动 3 分钟） |
| T-v03-04 | 「自动暂停坏源」开关 | 去掉开关，改坏源行「立即重试」按钮 | 退避是核心保障机制不应可关；用户真实需求是"现在重试一次" |
| T-v02-01 | 冷启动 ≤1.5s 进 CI 门禁 | 冷启动降级为发布手动回归项，体积门禁保留 | 无可自动化度量手段，强行自动化成本高 |
| T-v02-03 | 仅"导入 OPML / 手动添加源"两入口 | 补第三入口「浏览推荐源」（内置精选源列表） | 纯新手没有 OPML 文件，两入口都会卡住 |
| T-v03-02 | 每天最多检查 1 次 | 每 3 天 1 次 + 「启动时不检查」开关；补多源降级（R2 失败切 GitHub Release） | 降低打扰；隐私敏感用户可关；避免单一下载源不可达即失败 |
| T-v03-03 | 公证流程未写全 | 补 `notarytool submit --wait`（排队可能数分钟）+ 完成后 `stapler staple` | 公证是异步的，CI 不能提交后继续；不 staple 则离线用户仍被拦 |
| T-v02-02 新增 | 无 | 导入完成后轻提示「已添加 N 个源，M 个暂时无法连接」 | 首次批量抓取死链不能静默，给用户一个预期管理 |
| T-v02-04 新增 | 无 | 明确"今天/本周"时区 = 用户本地时区 | 避免实现时二义 |

## 二、v0.2 任务清单（装得上 / 不吓跑人）

### T-v02-01 ｜ 轻量门禁（R-01）
- **分层**：CI
- **目标**：把「安装包体积」钉成硬指标，超标即 CI 失败，防止悄悄变胖。
- **改动点**：
  - 在 `ci.yml` 或 `build-desktop.yml` 末尾新增 `size-budget` step：构建后读取产物体积（`apps/desktop/build/bin/Flore*.exe`、便携 zip、deb），超过阈值则 `exit 1`。
  - 阈值建议（写进注释，便于你拍板调整）：Windows 便携 zip ≤ 35MB、安装版 ≤ 45MB、deb ≤ 40MB。
  - **冷启动不做自动门禁**：无低成本自动化度量手段（且零遥测原则禁止埋点上报）。降级为发布手动回归项，写进发版 checklist：「新装冷启动到首屏可交互 ≤ 1.5s，人工验证」。
- **验收**：往 `release.yml` 故意塞个大资源后 CI 能红；正常构建能绿。
- **依赖**：无
- **估时**：S

### T-v02-02 ｜ 导入治理：只拉最近 N 天（R-04）
- **分层**：后端 + 前端
- **目标**：导入订阅源后，默认只回填最近 7 天文章，避免一次灌入几千条把人淹没。
- **改动点**：
  - 后端：新增全局设置 `initialFetchWindowDays`（默认 7），存 `Setting` 表。
  - `server/go/internal/services/fetcher.go`：当 `SourceHealth.LastSuccessAt` 为空（首次抓取）时，仅拉取 `pubDate >= now - windowDays` 的文章；非首次走正常增量。
  - 前端：设置页（`SettingsSourcesTab.tsx`）加一个「首次抓取范围」选项（7 天 / 30 天 / 全部），默认 7 天。**不做导入弹窗选择器**——窗口是全局行为，不是单次导入行为。
  - 新增：首次批量导入抓取完成后，前端轻提示「已添加 N 个源，M 个暂时无法连接」（M=0 时不显示后半句），给用户预期管理。
- **验收**：导入一个历史源，首屏只出现窗口内文章；改全局设置为「全部」后，新导入的源拉全量；导入含死链的 OPML 后出现汇总提示。
- **依赖**：无
- **估时**：M

### T-v02-03 ｜ 首次启动空状态引导（R-05）
- **分层**：前端
- **目标**：新用户打开软件第一眼知道「该干嘛」，而不是面对一片空白。
- **改动点**：
  - 复用 `EmptyState.tsx`，新增首启判定：当 `Source` 数为 0 时，`App.tsx` 主区渲染引导卡（图标 + 「欢迎使用 Flore」+ **三个入口**）：
    1. 导入 OPML —— 直跳现有 `ImportOPMLModal`；
    2. 手动添加源 —— 直跳添加源弹窗；
    3. **浏览推荐源** —— 打开内置精选源列表（写死的 JSON，约 10 个常用中文 RSS 源），点「订阅」即添加。**给没有 OPML 文件的纯新手一条活路**。
  - `Sidebar.tsx` 源列表为空时显示同款引导，而非空白。
  - 引导文案白话化（避免「暂无数据」这类死板词）。
  - 范围标注：**Web 版开局路径另案设计**（Web 无本地文件权限，不能导入本地 OPML），v0.2 仅覆盖桌面端。
- **验收**：清空数据库后首次启动出现引导；点「浏览推荐源」可一键订阅；导入一个源后引导消失。
- **依赖**：无
- **估时**：S

## 三、v0.3 任务清单（信得过 / 敢长期用）

### T-v03-01 ｜ 包管理器接入（R-02b）
- **分层**：CI / 文档
- **目标**：让用户用 `winget install flore` / `brew install --cask flore` 一键装，降低获取门槛。
- **改动点**：
  - 新增 `winget` manifest（`manifests/f/Flore/Flore/<ver>/`）提交到 winget-pkgs 或仓库 `assets/package-managers/`。
  - 新增 Homebrew Cask（`Casks/flore.rb`），`url` 指向 GitHub Release 的 dmg。
  - **不做 CI 自动提 PR**：发版后手动提交 manifest PR（附仓库链接与模板）；Release 说明里加一句「欢迎提交 winget/brew manifest」。等用户量起来再评估自动化。
- **验收**：本地 `brew install --cask flore` / `winget install flore` 能装上最新版。
- **依赖**：T-v03-03 → T-v02-05（先有稳定签名 dmg）
- **估时**：S

### T-v03-02 ｜ 更新启动自检查（R-02c 收尾）
- **分层**：前端
- **目标**：不用手动点「检查更新」，软件启动时后台静默查一次，有新版温和提示。
- **改动点**：
  - `SettingsAboutTab.tsx` 的挂载 `useEffect` 中，桌面端自动调一次 `checkForUpdate()`（节流：**每 3 天最多 1 次**，用 `Setting` 记 `lastUpdateCheckAt`）。
  - 新增设置项「启动时检查更新」（默认开），隐私敏感用户可关。
  - **多源降级**：检查 `update.json` 返回多个下载源（R2 优先，GitHub Release 备用），下载失败自动切换下一源；全部失败走现有 `updateManualUrl` 兜底提示手动下载。
  - 有新版本时，主界面角落轻提示「发现新版本 vX，点击更新」，不弹 Modal 打断。
- **验收**：发个测试版，旧版启动后能收到提示且不打扰阅读；关掉开关后不再自动检查；R2 不可达时能走 GitHub Release 下载。
- **依赖**：R-02c 后端已就绪
- **估时**：S

### T-v03-03 ｜ macOS 签名与公证（R-15 核心阻塞）
- **分层**：桌面壳 / CI（🔴 阻塞项，需你拍板预算）
- **目标**：让 macOS 用户双击不被 Gatekeeper 拦，否则「信得过」无从谈起。
- **改动点**：
  - `release.yml` macOS 段接入 Apple 开发者证书（`secrets.APPLE_CERT_P12` + `APPLE_API_KEY`），`codesign --deep --options runtime`。
  - **公证流程写全**：`xcrun notarytool submit --wait`（Apple 排队可能数分钟，CI 需等待/轮询到完成），公证通过后 **`xcrun stapler staple`** 把票据钉入应用包（否则离线用户仍被拦）。
  - 移除当前 ad-hoc 自签降级逻辑（保留为无证书时的 warning 回退）。
  - Windows 段确认 NSIS 安装版走 `secrets.WIN_CODESIGN_CERT` 真签名；若证书未配，保留 NSIS 并在 Release 说明标注「SmartScreen 会警告，属已知」。
- **验收**：干净 macOS 双击 dmg 安装无拦截（含离线场景）；Windows SmartScreen 不报未知发布者。
- **依赖**：需你提供 Apple 开发者账号 / 证书预算（见下方拍板项）
- **估时**：M（含证书配置对接与公证等待流程）

### T-v03-04 ｜ 源健康前端口径统一（R-09 收尾）
- **分层**：前端
- **目标**：把后端已有的「坏源 / 退避 / 失败次数」在界面上让人一眼看见，并可手动干预。
- **设计原则（异常才标记，健康保持静默）**：只标异常源，健康源不挂任何标记——"这一行没图标"本身就是健康信号，避免整列全是徽标制造噪音、反而淹没真问题。
- **改动点**：
  - `Sidebar.tsx` 源列表项**仅在异常时**显示徽标（橙=退避中 / 红=连续失败≥3），健康源零标记；hover 异常源显示 `lastError` 摘要。
  - 仅当存在异常源时，侧边栏源分组标题处显示一行轻量提示「N 个源异常」；全部健康时这行隐藏。
  - `SettingsSourcesTab.tsx` 坏源行显示告警 + **「立即重试」按钮**（绕过退避窗口，人工触发一次抓取尝试）。**不做「自动暂停坏源」开关**——退避是核心保障机制不应可关，用户真实需求是"现在重试一次"。
- **验收**：制造一个必失败源——仅该源变红/橙、侧边栏出现"N 个源异常"提示；其余健康源无任何标记；点「立即重试」可绕过后台退避立即尝试；恢复后标记消失、提示隐藏。
- **依赖**：R-09 后端已就绪
- **估时**：M

### T-v03-05 ｜ 未读分层（R-06，自 v0.2 移入）
- **分层**：前端
- **目标**：把未读按「时间 / 重要度」分层，降低未读焦虑，而不是一个数字吓死人。
- **说明**：v0.2 阶段不实现，优先保证「装得上 + 不吓跑人」；若 v0.2 时间充裕可提前。
- **改动点**：
  - `ArticleList.tsx` 顶部加分段控件：今天未读 / 本周未读 / 全部未读 / 星标，默认「今天未读」。
  - **v0.3 阶段纯前端客户端筛选**：按 `Item.PubDate` 在前端分组（小数据量下无性能问题），不新增后端接口参数。
  - 时区定义：**"今天 / 本周"一律按用户本地时区（系统时区）计算**，写入实现注释，避免二义。
  - `Sidebar.tsx` 对应分组展示各层未读数（复用 `Source.UnreadCount` 思路，新增聚合）。
- **验收**：切到「今天未读」只显示当日（按本地时区）；星标分组独立可点。
- **依赖**：T-v02-03（共用 EmptyState 引导）
- **估时**：M

### T-v03-06 ｜ 补齐 macOS 安装包形态（R-02a 收尾）
- **分层**：桌面壳 / CI
- **目标**：macOS 目前只产便携版，补上 `.dmg` 安装包，让普通用户能正常安装。
- **改动点**：
  - `release.yml` macOS 段新增 dmg 打包（`cmd/package-tool` 增加 `edition=dmg`，或 `create-dmg`）。
  - 产出 `flore-*.dmg` 上传 artifact + GitHub Release。
  - **与 T-v03-03 同批发布**：未签名的 dmg 照样被 Gatekeeper 拦，单独发意义不大。
- **验收**：Release 页面出现已签名 dmg，双击可拖入 Applications。
- **依赖**：T-v03-03（签名）
- **估时**：S

## 五、验收总闸（怎么算 v0.2 / v0.3 做完了）

- **v0.2 完成标志**：① 装包体积有 CI 门禁且不超标；② 导入订阅源默认只拉 7 天、死链有汇总提示；③ 新用户首启有引导（含推荐源入口）。
- **v0.3 完成标志**：① `winget`/`brew` 能装（手动 PR）；② 启动自动查更新（3 天节流 + 多源降级 + 可关）；③ macOS 不被 Gatekeeper 拦（公证 + staple）；④ 坏源可见、可「立即重试」；⑤ 未读可分层切换。
