## 4. MAJOR 问题详情

### M-A1: `installer.nsi` 仍包含已不再产出的 `florebackend.exe`
- **文件**：`apps/desktop/installer.nsi:7, 56`
- **类别**：架构 / 打包
- **问题**：mac 的 `package-tool` 已不再拷贝独立后端二进制（删除了 `beBin` 参数与拷贝逻辑），但 NSIS 脚本仍写 `File "build\bin\florebackend.exe"`（第 56 行），且头部注释称"额外包含 florebackend.exe"（第 7 行）。
- **影响**：Windows **setup 安装版**构建（makensis 阶段）会因文件缺失而失败。mac 自衍生架构下分发包不再含该文件。
- **建议修复**：删除第 56 行 `File "build\bin\florebackend.exe"`，并修正第 7 行注释为"后端已编入主程序（--backend 自衍生）"。

### M-R1: `apply_windows.go` 更新脚本仍 `taskkill florebackend.exe`，无法停止真实后端
- **文件**：`apps/desktop/internal/updater/apply_windows.go`（`buildApplyScript` 模板 `taskkill /F /IM florebackend.exe`，约第 140 行）
- **类别**：可靠性（Windows 自动更新正确性）
- **问题**：自衍生架构下后端是 `Flore.exe --backend`（与主程序同二进制、不同参数），不再有 `florebackend.exe` 进程。更新脚本杀的是不存在的进程名 → 旧后端继续运行并持有 `reader.db`/WAL。
- **影响**：更新覆盖文件并重启 `Flore.exe` 后，新实例 `startBackends()` 启动 `--backend` 子进程绑定同一 SQLite → **SQLITE_BUSY / WAL 锁冲突**，或旧后端继续服务陈旧数据。
- **建议修复**：更新脚本按"命令行含 `--backend` 的 `Flore.exe`"特征定位并终止真实后端子进程；或依赖已绑定的 Job Object（父进程退出时由内核连带终止），并在 xcopy 前确认后端子进程已退出。

1. **后端自衍生架构设计正确并已统一**：`main.go:runBackendMode` + `server/go/backend.Start()` + `backend.go` 用 `os.Executable()+["--backend"]` 自衍生，从根上消除 Gatekeeper 对嵌套独立二进制的静默拦截。

3. **后端并发与生命周期处理细致**：`backendMutex`/`stopOnce`/`exited` channel、M1 启停竞态回收、M9 唯一 `cmd.Wait()` 回收点、端口文件消除 TOCTOU、Job Object 绑定（C2）杜绝孤儿进程。
4. **安全细节到位**：`generateAPIToken` fail-closed（`os.Exit(1)` 不降级空 token）、日志掩码 `FLORE_API_TOKEN`（N1）、`startProcess` 仅允许绝对路径（M4）。
5. **dev 的 RSS 去重修复质量高**：`filterValidItems` 按 link 去重 + 空 link 过滤，避免 UNIQUE 冲突使整事务回滚；配套 `fetcher_dedup_test.go`；`time.go` 错误信息修正正确。属共享 `server/go` 代码，合并后无冲突。
6. **合并流程执行正确**：最终 `mac→dev` FF 合并使两分支完全一致，避免了"取错一侧文件"的典型合并陷阱；`go.sum` 经 `go mod tidy` 完整重算无残留冲突标记。
7. **前后端启动窗口对齐**：`api.ts` 轮询从 20 次提升至 75 次（≈15s），与后端首次启动含迁移的最长时间对齐。
